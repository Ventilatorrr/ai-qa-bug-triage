About this policy

This policy describes how the AI QA Bug Triage application handles data. It does not yet identify the data controller, provide a privacy contact, or state the applicable jurisdiction and legal basis for each processing purpose.

Accounts and project information

Registration collects an email address and password. The application stores a password hash, not the plain-text password, and uses the credentials to authenticate access. Login issues an access token. These details are required to create and use an account. Registered users can keep their accounts and projects and return to them later.

The application stores accounts, project names, memberships and roles, and user-supplied bug reports, including titles, descriptions, environment, reproduction steps, expected and actual results, versions, classifications, assignments, lifecycle information, authorship and timestamps. It uses this information to provide project collaboration and bug management. Authorized members can view their project's reports and member email addresses and roles.

Try Demo

Visitors can start a Demo from the Login page without registering. Each Demo creates five generated accounts with example.com email addresses and random passwords that are stored as hashes and never shown. The visitor is signed in as the Demo's Project Owner. Each Demo also creates two projects: one with fictional E-Commerce bug reports and one with copies of this project's genuine development defect reports, which were reviewed for sensitive information before inclusion.

Demo accounts and data, including anything the visitor adds or changes, are stored in the application database in the same way as other accounts and projects. Demo access ends when the visitor logs out or the session expires; because the generated credentials are never shown, the Demo cannot be reopened afterwards. Demo data is not automatically deleted when access ends.

The number of Demos that can be created is limited to protect the service. These limits do not use IP addresses. Do not enter personal or confidential information in a Demo.

Optional AI Assist and OpenAI

AI Assist contacts OpenAI only when an eligible user explicitly requests it and the service is configured. It sends the current form's Title, Affected Version, Environment, Description, Steps to Reproduce, Expected Result, Actual Result, Severity, Priority and Assignee ID, including unsaved edits.

It also sends up to five recently updated reports from the same project, with those fields, internal report IDs and bug numbers, and eligible assignees' user IDs, email addresses and roles. Long historical text is shortened. The report being edited is excluded from this historical context. Historical content may have been entered by other project members.

Application-managed authentication tokens, session credentials and configuration secrets are not automatically added to AI context. User-supplied text is not automatically checked for every possible secret. Do not include passwords, API keys, sensitive or unnecessary personal information, or confidential material in reports or AI requests.

Suggestions are advisory: review actions change only the form, and Create or Save stores the chosen values. To enforce daily usage limits, the application records the account and date of each AI Assist request sent to OpenAI. The data-sharing notice can be dismissed; dismissal is an informational preference, not consent or a change to the data sent.

The application requests store=false from OpenAI. This does not establish zero retention or other provider guarantees, and this policy does not describe OpenAI's own retention, data-use or transfer practices. See OpenAI's API data controls.

Hosting and other service providers

The application is hosted on Render. Hosting infrastructure may process technical connection information such as IP addresses, browser details and request times. This policy does not describe the server location, subprocessors, backup arrangements, hosting logs or any international transfers, and no hosting location or transfer safeguard is promised.

The project and bug report pages load the Oxanium font from Google Fonts, so your browser requests it from Google's servers, which receive technical connection information such as your IP address. The page address is not sent as a referrer with this request.

Browser storage

The frontend uses localStorage for the access token, theme, bug page-size preferences and the shared dismissed AI-notice preference. It uses sessionStorage for per-user/project sorting and temporary interface feedback. Logging out removes the access token; other preferences remain until changed or browser storage is cleared. Clearing storage can sign you out and make the notice reappear. If storage is unavailable, dismissal may last only for the current page.

The current frontend does not implement advertising or analytics tracking. This policy does not cover any cookies the hosting platform may set.

Security, retention and deletion

The application uses password hashing, authenticated API requests, project membership checks and role-based permissions. No system can guarantee complete security; use fictional, non-sensitive content for portfolio demonstrations.

No automatic account, report or Demo retention schedule is currently implemented. Authorized project actions can delete reports and projects or remove memberships, but there is no self-service account-deletion feature. Retention periods for accounts, project data, Demo data, logs, backups and provider copies have not been defined, and there is no formal privacy-request or deletion process. Removing a project member does not delete that person's account or all content they previously supplied.

Privacy rights and requests

Depending on the applicable law and circumstances, you may have rights to access, correct or erase personal data, restrict or object to processing, receive portable data, and withdraw consent where processing relies on consent. You may also be able to complain to the data protection authority responsible for your location. These rights can have conditions and exceptions.

This page does not yet explain how to submit privacy requests. The dismissible AI notice does not establish a legal basis or record consent.
