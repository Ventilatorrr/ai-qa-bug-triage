Pre-deployment draft — updated 14 October 2026

Draft status and contact

This draft describes the current AI QA Bug Triage implementation and its planned public portfolio use. It is not a confirmation of final deployment arrangements. Before publication, the operator must identify the data controller, publish a working privacy contact, and confirm the applicable jurisdiction and legal basis for each processing purpose. No privacy contact has been confirmed yet.

Accounts and project information

Registration collects an email address and password. The application stores a password hash, not a plain-text password, and uses the credentials to authenticate access. Login issues an access token. Providing these details is required to create and use an account.

The application stores accounts, project names, memberships and roles, and user-supplied bug reports, including titles, descriptions, environment, reproduction steps, expected and actual results, versions, classifications, assignments, lifecycle information, authorship and timestamps. It uses this information to provide project collaboration and bug management. Authorized members can view their project's reports and member email addresses and roles.

Optional AI Assist and OpenAI

AI Assist contacts OpenAI only when an eligible user explicitly requests it and the service is configured. It sends the current form's Title, Affected Version, Environment, Description, Steps to Reproduce, Expected Result, Actual Result, Severity, Priority and Assignee ID, including unsaved edits.

It also sends up to five recently updated reports from the same project, with those fields and internal report IDs, and eligible assignees' user IDs, email addresses and roles. The edited report is excluded from historical context; there is no separate saved-version snapshot. Historical content may have been entered by other project members.

Application-managed authentication tokens, session credentials and configuration secrets are not automatically added to AI context. User-supplied text is not automatically checked for every possible secret. Do not include passwords, API keys, sensitive personal information or confidential third-party material in reports or AI requests.

Suggestions are advisory: review actions change only the form, and Create or Save persists the chosen values. The data-sharing notice can be dismissed; dismissal is an informational preference, not consent or a change to the data sent.

The application requests store=false from OpenAI. This does not establish zero retention or other provider guarantees. Before deployment, confirm the provider account's applicable terms, retention, data-use settings and transfer arrangements. See OpenAI's API data controls.

Hosting and other service providers

The hosting provider, server location, subprocessors, backup arrangements and any international transfers have not been confirmed for public deployment. Hosting infrastructure may process technical connection information such as IP addresses, browser details and request times. Actual logging, access and retention must be documented before publication. No hosting location or transfer safeguard is promised by this draft.

Browser storage

The frontend uses localStorage for the access token, theme, bug page-size preferences and the shared dismissed AI-notice preference. It uses sessionStorage for per-user/project sorting and temporary interface feedback. Logging out removes the access token; other preferences remain until changed or browser storage is cleared. Clearing storage can sign you out and make the notice reappear. If storage is unavailable, dismissal may last only for the current page.

The current frontend does not implement advertising or analytics tracking. Hosting-level cookies or future integrations must be assessed and disclosed before deployment.

Security, retention and deletion

The application uses password hashing, authenticated API requests, project membership checks and role-based permissions. Public deployment still requires confirmation of HTTPS, hosting and database access, backups and operational security. No system can guarantee complete security; use fictional, non-sensitive content for portfolio demonstrations.

No automatic account or report retention schedule is currently implemented. Authorized project actions can delete reports and projects or remove memberships, but there is no self-service account-deletion feature. The operator must confirm retention periods or criteria for accounts, project data, logs, backups and provider copies, and establish a privacy-request and deletion process before publication. Removing a project member does not delete that person's account or all content they previously supplied.

Planned recruiter demonstrations

Temporary recruiter demo accounts and fictional demonstration data are planned, not currently implemented as an automated feature. Access, expiry, cleanup and separation from real user data must be defined before those accounts are offered. This draft does not promise automatic expiry or deletion.

Privacy rights and requests

Depending on the applicable law and circumstances, you may have rights to access, correct or erase personal data, restrict or object to processing, receive portable data, and withdraw consent where processing relies on consent. You may also complain to the relevant supervisory authority; for UK data protection matters, see the Information Commissioner's Office. These rights can have conditions and exceptions.

Before public registration opens, this page must provide the operator's identity and privacy contact, explain how to submit requests, and confirm the applicable legal bases and rights. The dismissible AI notice does not establish a legal basis or record consent. Update this policy when the confirmed deployment or data practices change.
